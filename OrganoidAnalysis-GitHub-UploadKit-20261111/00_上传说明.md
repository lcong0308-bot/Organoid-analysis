# GitHub 上传说明

本目录已分为仓库文件、下载附件和维护者资料。不要将整个工作目录上传。

## 第一步：仓库文件

将 `01_仓库文件` **内部的文件和文件夹**上传到仓库根目录，不要多套一层 `01_仓库文件`，也不要只上传仓库 ZIP。根目录应直接看到 README.md、docs、SUPPORT.md 等。

在仓库选择 Add file → Upload files，上传后检查 README 图片。`.github` 内是反馈模板，`.gitignore` 是排除规则；Windows 若隐藏点开头文件，请核对两者是否一并上传。推荐用 GitHub Desktop 导入整套目录，或在网页中分次上传。当前文件数量少于 100，单文件小于 25 MiB。

官方说明：[上传文件](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。

## 第二步：Releases 下载附件

进入 Releases → Draft a new release，建议 Tag 为 `v2.21`（若已有此标签，先核对已有版本，勿覆盖）。标题可填 `Organoid Analysis 2.21 — Windows x64`。将 `03_发布管理_不要上传仓库/RELEASE_NOTES.md` 复制到说明栏。

把 `02_Releases附件` 中的软件 ZIP、图文指南 ZIP、获准公开后的示例 ZIP 和 SHA256SUMS.txt 作为附件上传。约 240 MB 的软件 ZIP 不要放入仓库文件列表。

先 Save draft；完成发布前检查后再由你点击 Publish release。官方说明：[管理 Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。

## 第三步：发布前必须确认

- 明确账号获取渠道。当前包不是免登录或已去除有效期的版本。
- 确认软件、模型和示例数据有对外分发权限，补齐第三方许可材料。
- 确认正式使用条款；本次未擅自赋予商业使用或再分发许可，也未选择开源许可证。
- 补上平台名称、官网和联系渠道，当前不虚构这些信息。
- 审查截图中的用户名、路径及图像是否适合公开；部分标注图经图像工具重绘，仅用于区域导览。
- 在独立 Windows 环境测试解压、登录、示例分析与导出。

## 不要上传

`03_发布管理_不要上传仓库` 和本说明供你操作使用；不要上传账户数据、开发者版、内部源码、构建目录或私人实验数据。

本次仅整理本地文件，没有创建仓库、上传文件或发布 Release。外层总 ZIP 是交付给维护者的搬运包，不应作为普通用户的软件附件。
